# goose_ar

모자 쓴 캐릭터를 내 방 바닥에 소환하고, 부르면 걸어오게 하는 웹 AR (안드로이드 Chrome, WebXR).
계획과 마일스톤은 [PLAN.md](PLAN.md)를 참고하세요.

## 개발

```bash
npm install
npm run dev        # http://localhost:5173
```

폰에서 테스트할 때는 USB로 연결하고 `adb reverse tcp:5173 tcp:5173` 후 폰 Chrome에서 `http://localhost:5173`을 엽니다.
(WebXR은 HTTPS 또는 localhost에서만 동작합니다.)

## AR 사용 (M2)

안드로이드 Chrome에서 페이지를 열고 **AR 시작**을 누르면 카메라가 켜진다.
바닥을 천천히 비추면 흰 링이 뜨고, 탭하면 그 자리에 오리가 서서 나를 바라본다. **다시 놓기**로 위치를 바꾸고, AR을 끝내려면 **뒤로 가기**(제스처나 버튼)를 누른다. 화면에는 종료 버튼이 없다. 끝나면 일반 뷰어로 돌아간다.

오리를 놓으면 버튼이 더 나온다.
- **이리 와**: 오리가 내 쪽으로 몸을 돌리고 걸어와서 `STOP_DISTANCE_M`(0.5m) 앞에서 멈춘다. 오는 중에도 내가 움직이면 계속 따라온다.
- 안내 문구는 유리 상자 없이 글자와 상태 점으로만 잠깐 보인다(걷는 중 하늘색, 도착 민트, 춤 주황). 바닥을 찾는 동안에는 가운데에 안내 카드가 뜬다.
- **바닥을 탭**: 오리가 이미 놓여 있으면, 탭한 곳으로 걸어간다. 도착할 곳에는 주황색 링이 표시되고, 걷는 도중 다시 탭하면 목적지가 바뀐다. 벽이나 하늘을 탭하면 무시한다. (오리가 서 있는 바닥 높이의 평면과 터치 방향이 만나는 점으로 계산하므로 평평한 바닥에서 정확하다.)
- **춤 춰**: 춤을 한 번 추고 Idle로 돌아간다.
- 멈춰 있을 때와 춤출 때는 천천히 나를 바라본다.

- **촬영 모드**: 버튼과 안내 문구를 전부 숨긴다. 이 상태에서 폰의 화면 캡처나 화면 녹화로 오리와 함께 찍는다. 오른쪽 아래의 흐린 `UI` 버튼으로 복구한다.
- 오리 발밑에 부드러운 그림자가 생겨서 바닥에 서 있는 것처럼 보인다 (`src/duck/shadow.ts`).

걷기 튜닝은 `src/config.ts`: `WALK_SPEED_MULT`(걸음 빠르기, 속도도 같이 올라가서 발은 미끄러지지 않음), `STOP_DISTANCE_M`, `GO_STOP_DISTANCE_M`, `MAX_TAP_DISTANCE_M`, `TURN_RATE`.

- 필요 조건: ARCore 지원 폰 + Chrome (Google Play Services for AR 설치)
- 오리 크기는 `src/config.ts`의 `DUCK_HEIGHT_M`(기본 0.3m)
- AR 미지원 기기에서는 버튼이 비활성화되고 일반 3D 뷰어만 동작

## 바닥 인식

바닥 위치는 폰의 ARCore가 찾고, 앱은 화면 가운데 방향의 히트 테스트 결과를 받아 링을 띄운다(`src/xr/ar.ts`).

- **평면과 특징점 둘 다 요청**(`entityTypes: ['plane', 'point']`): 평면은 ARCore가 확신해야 나와서 가장 늦다. 특징점 히트는 더 일찍, 무늬 없는 바닥에서도 나온다. 대신 높이가 몇 cm 어긋날 수 있어서 어긋나면 **다시 놓기**를 쓴다. 이 옵션을 모르는 브라우저는 평면만 쓴다.
- **위를 향한 면만 바닥으로 인정**(`facesUp`): 벽(법선 0)과 천장(-1)은 링이 뜨지 않는다. 책상 윗면 같은 수평면은 된다.
- **찾는 시간이 길어지면 안내가 바뀐다**(0초, 7초, 16초): 천천히 움직이기 → 1~2m 앞에서 비추기 → 어둡거나 반짝이는 바닥 팁.
- **16초가 넘으면 "그냥 놓기"**: 폰 높이를 기준으로 추정한 바닥(폰 아래 1.25m)에, 화면 가운데가 그 바닥과 만나는 곳에 놓는다(`estimateFloorPoint`). 바닥을 찾았다 놓쳤다 해도 16초 시계는 다시 시작하지 않는다.
- 브라우저가 화면 위 UI(dom-overlay)를 허락하지 않으면 AR 시작을 막고 이유를 알려 준다.
- **삼성 인터넷과 앱 안 브라우저**(카카오톡, 인스타그램, 네이버 등)는 이 AR을 제대로 못 돌린다. 갤럭시는 기본 브라우저가 삼성 인터넷이고 채팅 앱의 링크는 앱 안에서 열려서 흔한 원인이다. 그런 브라우저를 알아보면 뷰어의 안내 칩에 "Chrome으로 열어 주세요"를 보여 준다(`src/xr/browser.ts`).

### 진단 화면 (`?diag`)

폰에서 바닥이 안 잡히는 등 직접 볼 수 없는 문제는 주소 뒤에 `?diag`를 붙여서 연다(`src/ui/diag.ts`). 화면 위쪽에 상태가 글자로 뜨고, AR 중에도 보인다. 스크린샷 한 장이면 원인을 알 수 있다.

| 줄 | 뜻 |
|---|---|
| `ua`, `gpu`, `float rt` | 폰과 브라우저, 그래픽 칩. `float rt`가 false면 환경 반사를 못 만드는 폰 |
| `webxr AR` | false면 이 폰·브라우저는 AR 미지원 |
| `AR granted` | 세션이 실제로 허락받은 기능. `hit-test`가 없으면 바닥을 못 찾는다 |
| `page UI (dom-overlay)` | `NONE`이면 안내 카드와 버튼이 화면에 안 보인다(그 경우 AR 시작을 막고 안내를 띄운다) |
| `tracking` | `NO POSE`이면 폰 위치 추적이 안 됨, `position guessed`는 추적이 불안정함 |
| `duck` | 오리가 보이는 상태인지, 위치, 카메라와의 거리, **화면 안에 들어오는지**(`IN VIEW`/`out of view`) |
| `drawn` | 그래픽 칩이 마지막 프레임에 그린 호출·삼각형 수. 오리가 `IN VIEW`인데 삼각형이 적으면 오리가 안 그려지는 것 |
| `floor hits` | 매 프레임 바닥 후보 수(`raw`), 위를 향한 것(`facing up`), 가장 큰 up 값(바닥 1, 벽 0, 천장 -1) |
| `search` | 바닥을 찾은 지 몇 초째인지와 안내 단계 |
| 맨 아래 | 마지막 오류 6개 |

### 오리가 안 나올 때 (불러오기와 그래픽)

- **첫 접속에서 화면이 비지 않는다**: 선택 화면이 코드가 도착하는 즉시 뜨고, 카드마다 "불러오는 중…"이 보이다가 오리가 준비되는 대로 채워진다. (느린 통신, 약 4Mbps에서 선택 화면까지 13.7초 → 2.4초.)
- **받기에 실패하면 알려 준다**: 한 마리만 실패하면 그 카드만 "불러오지 못했어요"가 되고, 고른 오리가 실패하면 다른 오리로 열면서 안내하고, 둘 다 실패하면 새로고침을 안내한다.
- **그래픽 칩이 유리 재질을 못 그리면**(셰이더 오류) 자동으로 단순 재질로 바꿔서 오리가 투명해지지 않게 한다. 환경 반사를 만들 수 없는 칩에서는 반사 없이 진행하고, 그때는 밝은 조명을 쓴다.
- 주소 `?look=plain`: 기존 오리만(가장 단순한 경로). `?noenv`: 환경 반사 끄기. `?noshadow`: 그림자 끄기. **`?safe`**: 세 가지를 한꺼번에(기존 오리, 반사 없음, 그림자 없음). "어느 기능 때문에 안 나오는지" 가려내는 데 쓴다.
- 주소 `?cube`: AR 중에 자홍색 상자 두 개를 가장 단순한 재질로 그린다. 하나는 카메라 앞 0.6m에 붙어 있고, 하나는 놓은 오리 위에 떠 있다. 상자는 보이는데 오리만 안 보이면 오리를 그리는 쪽 문제다.

## PC에서 UI 미리보기

AR은 폰에서만 되지만, 조작부 디자인은 PC에서 볼 수 있다.

- `http://localhost:5173/?ui=ar` : AR 화면의 조작부를 일반 뷰어 위에 띄워서 보여 준다.
- `?ui=ar&photo` : 촬영 모드 상태.
- `?ui=ar&scan` : 바닥을 찾는 중 상태. `?ui=ar&msg=도착했어요&tone=done` : 문구와 점 색(info, walk, done, dance) 확인.
- 크롬 개발자 도구에서 폰 크기(예: 390×780)로 보면 실제와 비슷하다.

`main`에 푸시하면 GitHub Pages로 배포됩니다. 처음 한 번 저장소 Settings → Pages → Source를 **GitHub Actions**로 바꿔야 합니다.

## 옛 화면이 보일 때 (캐시)

GitHub Pages는 브라우저가 `index.html`을 약 10분간 캐시하게 해서, 배포 직후에도 폰에 옛 화면이 보일 수 있다.

- 일반 뷰어 오른쪽 위에 현재 빌드 번호(`v97aa2f8` 같은 커밋 번호)가 보인다. 마지막 배포 커밋과 같은지 확인하면 된다.
- 열 때 서버의 `version.json`과 비교해서 더 새 버전이 있으면 `?v=<번호>` 주소로 한 번 자동 이동한다.
- 급하면 주소 뒤에 `?v=아무값`을 붙여서 연다.

## 오리 두 종류 (유리 / 일반)

| 선택 | 모델 | 설명 |
|---|---|---|
| **유리 질감** | `public/models/duck_glass.glb` (1.1MB) | 새 오리(`assets/roomducks_duck_only.blend`). 반질반질한 코팅 재질 |
| **일반** | `public/models/duck_plain.glb` (2.6MB) | 기존 오리 그대로(`assets/duck.blend`) |

**처음 접속하면 선택 화면**이 뜬다(`src/ui/picker.ts`). 두 오리가 각각 3D로 돌아가고, 탭해서 고르면 그 오리로 시작한다. 선택은 폰에 저장되어(`localStorage`의 `goose-ar-look`) 다음부터는 **고른 오리만 내려받고** 바로 들어가며, 일반 뷰어의 **질감 바꾸기** 버튼으로 다시 고를 수 있다.

- 주소 `?look=glass` / `?look=plain`: 선택 화면을 건너뛰고 그 오리로 연다(저장된 값은 바꾸지 않는다).
- 주소 `?pick`: 선택 화면을 강제로 띄운다.
- 기본값은 `src/config.ts`의 `DEFAULT_LOOK`(저장된 게 없을 때).
- 오리마다 조명이 다르다(`src/duck/looks.ts`의 `LIGHTING`). 유리 오리는 코팅이 번쩍이지 않게 환경광과 태양광을 낮추고 코팅도 약하게(`applyGlassLook`) 두었고, 일반 오리는 원래 조명 그대로다.
- 선택 화면의 두 오리는 `duck.clone()`으로 만든 복사본이고, 앱의 렌더러 하나가 카드 영역마다 나눠서 그린다.

### 에셋 만들기

- `tools/export_glb.py`: 새 오리 blend → `duck_glass.glb`. 눈·볼터치 텍스처 굽기, 폴리곤 줄이기, 모자·돈다발 고정, 제자리 Idle/Walk/Dance 제작까지 한다 (`pip install bpy` 필요).

```bash
python tools/export_glb.py assets/roomducks_duck_only.blend public/models/duck_glass.glb
```

- 기존 오리(`duck_plain.glb`)는 예전 스크립트로 만들었다. 다시 만들어야 하면 커밋 `e940252`의 `tools/export_glb.py`를 쓴다.
- `assets/roomducks_duck_only.blend`에는 새 오리의 보송한(Plush) 재질도 남아 있다(지금은 쓰지 않음).

## 애니메이션 클립

| 클립 | 길이 | 설명 |
|---|---|---|
| `Idle` | 2.0초 (루프) | 숨쉬기 |
| `Walk` | 0.667초 (루프) | 뒤뚱뒤뚱 걷기. 발이 미끄러지지 않는 이동 속도는 모델 단위로 **2.1 units/초** (`2 × STRIDE ÷ (16프레임 ÷ 24fps)`). 앱에서 오리 크기를 곱해서 쓴다. |
| `Dance` | 유리 오리 8초, 일반 오리 10초 (한 번) | 춤. 끝나면 대기로 돌아간다 |

두 오리 모두 클립 이름이 같고(`Idle`, `Walk`, `Dance`), 한 오리의 세 클립은 같은 노드를 모두 제어한다. 클립을 바꿀 때 값이 남지 않도록 의도적으로 맞춰 둔 것이다. 걷는 간격이 같아서 발이 미끄러지지 않는 속도(2.1 units/초)도 두 오리에 똑같이 쓴다.
뷰어에서 `?clip=Walk&t=0.2&cam=side`로 특정 포즈를 고정해서 볼 수 있다.
